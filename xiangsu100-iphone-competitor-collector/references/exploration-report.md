# 探索报告：先回答竞品怎么做

当用户只想了解某项任务的不同解法、共性与差异时使用。材料可以来自截图、录屏、文档或本轮授权的真实采集。没有改版目标也可以完成；不要为了填写字段虚构目标产品、问题或方案。用户已明确要改版时，仍走设计决策契约，不用探索模式降低要求。

## 最小输入与产出

输入：研究问题、共同用户任务与范围、研究对象和材料路径。缺少用户背景可标明最小假设；只补问会改变比较口径的信息。

产出 `exploration-report.md` 和同内容的 `exploration-report.html`，由 Agent 根据实际证据生成；本模式没有专用自动语义评分器。用 Markdown 作为当前文字来源，同步更新 HTML。不要求 `cross-analysis.json`、`target_baseline`、`target_decision`、`redesign_summary` 或 `ux-analysis.json`，也不通过 `--allow-legacy` 假装通过设计报告验收。已有真实运行的 manifest、events、图库和覆盖记录原样保留；探索报告引用它们，不能替代采集验收。

报告包含以下内容，可按材料多少合并章节：

1. **问题与范围**：要解释什么，观察了哪些平台/频道，条件是否可比。无改版对象时明写“本轮无目标产品改版任务”。
2. **任务流程与证据范围**：起点、关键决定、相关分支、返回/异常，以及已观察或未知。静态截图不连成已实测路径；不存在的流程证据不强填。
3. **并排比较**：按用户决定组织，写各产品可见信息、操作机制、相同点与差异。保留关键原图、编号和可打开的来源；录屏注明时间点，文档注明页码。
4. **解释与条件**：哪种机制可能支持哪种判断、依赖什么条件、有什么代价或替代解释。没有用户测试时，效率、理解与转化结论只能是待验证推断。
5. **研究结论**：逐一回答问题，说明确认、修正、新发现与无法判断的内容。未观察到不能写“无此功能”，局部证据不能推出整体优劣。
6. **未解问题**：只列会改变判断的缺口，以及最小补证办法。下一步可以是验证解释，也可以到此结束；不强制改版、补采或长期跟踪。

例如研究会员介绍：可以比较价格、内容范围与试用入口怎样表达，再说明“价格优先可能适合预算判断，内容优先可能适合价值判断，实际理解效果未知”。无需给某个产品新增模块，也不能断言哪种表达转化更高。这是教学例子，不是产品事实。

## 完成检查

- 每个研究问题都有证据支持的回答或具体未知原因；比较条件与范围没有变化。
- 每条关键事实能回到原始资料，推断和效果未验证有明确标注。
- 原图经过审阅且无不应展示的个人信息；缺图片时如实说明，不生成假截图充证据。
- HTML 与 Markdown 判断一致；检查来源链接和嵌入图片，打开 HTML 核对正文、图片与布局。无法完成浏览器检查时如实标未验证。
- 完成意味着本轮问题得到有边界的回答，不意味着用户效果通过测试。不得把本模式称为已通过 schema-v2 或横向设计报告校验。

用户后续明确要改版时，再将当前观察作为来源接入 [设计报告契约](cross-report-contract.md)，补目标产品现状与取舍，保留探索报告历史版本。
