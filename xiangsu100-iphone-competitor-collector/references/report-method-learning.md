# 从优秀竞品报告中学习分析方法

当用户提供竞品分析报告，要求“学习、借鉴、融入我们的方法”时，任务是提炼报告的研究组织、分析动作、归纳方式和结果表达。优先回答“它做得好的地方是什么、为什么对分析有用、我们以后具体怎样做”。以用户确认的学习目标为主，不自动转成报告质量评审、问题审计或对案例产品的改版。

本参考将可迁移做法融入已有 [分析方法](analysis-result-design.md)、[横向分析](cross-competitor-analysis.md) 和 [体验框架](ux-analysis-framework.md)。它不是新增固定维度或 schema，按任务选择使用。原件、品牌、截图、页码和案例版本留在项目来源与学习记录中；通用方法只保留可复用的分析动作。

## 一、阅读参考报告时提炼什么

每个借鉴点写四项：

1. **原报告的做法**：指出具体页面、段落、图表或组织方式。
2. **方法价值**：解释它帮助分析者看清什么、帮助读者作出什么判断。
3. **融入位置**：选样、任务拆解、模块观察、横向比较、归纳、设计推导或结果交付。
4. **以后怎么用**：明确新增或强化的分析动作、输出形态，并给一个简短示范。

已有规则能够覆盖时，增加具体操作说明和样例；确实出现新问题时才扩展问题库。批注、统计、历史结论保留出处和上下文，必要边界紧邻借鉴点简述；除非用户要求评审，不另起大篇幅评价原报告不足。

## 二、十项可复用做法

### M01 按研究问题分配竞品角色

先明确研究要帮助目标产品决定什么，再为样本分配用途。直接竞品用于整体任务对照；相关服务或跨行业样本用于局部机制参考。可以区分核心、补充和专项研究对象，说明各自要看什么。

**输出：** “研究问题—参考对象—重点观察内容”短表。不同层次不代表产品整体优劣，也不要求为每层凑固定数量。

### M02 先建立业务分类，再比较页面

把不同产品的功能名转为可比较的对象，如内容类型、服务类型、获取/售卖方式、权益和用户状态。多媒体资源和咨询服务可能共享部分结构，也可能需要不同流程。

**输出：** 一张够用的类型映射表。分类直接决定分组和比较口径；不用一份复杂业务模型作为每次截图分析的前置门槛。

### M03 用用户旅程组织研究主线

用用户阶段串起页面，例如服务前/中/后、发现/了解/试用/获得/使用。先呈现整段任务，再选关键页面和分支展开。阶段名称、起止点以本项目范围为准。

**输出：** 阶段总览及重点流程；每阶段说明用户任务、触点、竞品做法和可借鉴机制。购买后、生成后等后续环节按任务需要纳入，不因出现结果页就默认研究完成。

### M04 将截图转为可比较的结构

在保留原图的同时，用区域标注、语义色块、线框或结构顺序，显示基础信息、价值说明、内容目录、主要操作等模块。标记的目的是解释模块职责、顺序和关系。

**输出：** “原截图 + 模块结构 + 分析说明”。同一图组使用一致的语义图例；必要处放大。分析既保留内容结构，也关注层级、位置、标签、卡片与控件如何帮助用户判断。

### M05 比较同一任务的不同解决方式

将不同产品解决同一问题的方式并排，如信息一次收集/分阶段补充、就地面板/独立页面、卡片推荐/共同字段对比。写清触发条件、关键动作、结果和返回关系。

**输出：** “方式—适用场景—具体机制—任务作用”的对照。重点解释不同做法如何工作，比较的形式随任务选择，不默认总评分。

### M06 从多个样本中归纳共性、差异和可复用模式

逐项观察后，总结哪些结构或流程相似、哪些因任务或资源类型不同而变化。共性可形成基础模式；差异可形成变体。选择有代表性的样本说明即可，不重复抄写所有竞品。

**输出：** “共性结构—差异变体—使用条件”。直接写清这轮研究提炼出了什么；材料中出现频率不自动等于效果优劣。

### M07 每个主题形成阶段性结论

一个阶段或主题分析结束后，立即收束“发现了什么值得借鉴的机制—为什么有价值—目标项目可怎样应用”。最后再汇总跨主题的关键认识和行动顺序。

**输出：** 章节短结论与总览。报告有局部发现，也有整体结论；完整截图作为依据保留，读者不必自行从大画板中归纳。

### M08 从洞察逐步推导设计方向

将研究发现与目标用户、业务诉求结合，提炼设计原则，再落到体验关键词、场景机会点和具体方案。需要发散时可用场景树、工作坊或草图；简单改版可压缩中间步骤。

**输出：** “研究依据—目标诉求—设计原则—场景机会—方案”的对应关系。原则应帮助作选择，例如临时查看保留原任务上下文；不只写抽象口号。新方案保留适用条件与验证任务。

### M09 同时考虑设计建议和复用资产

根据研究目的决定输出：当前项目怎么改，以及有哪些可复用页面/模块/流程模式。通用能力建设尤其需要第二类；单点改版可以只交付第一类。

**输出：** 建议清单与模式卡。模式卡最少说明适用任务、稳定结构、可变部分、关键状态和使用边界；可以是草图或结构模板，实施状态另记。

### M10 结合目标能力明确应用与先后顺序

将可借鉴机制与目标平台、内容、数据和业务能力对应，形成采用、调整、保持、暂缓或拒绝的决定，再落到页面模块与实施先后。

**输出：** 沿用已有 `target_decision` 和 `redesign_summary`，写具体改动、依赖、保留项及验证。维度重要性、研究选样优先级与建设行动顺序分别解释。

## 三、融入实际分析的七步工作顺序

1. **明确问题、选择样本**：围绕目标分配竞品角色（M01）。
2. **分类、梳理旅程**：对齐业务对象，找到任务主线（M02、M03）。
3. **拆解关键截图与流程**：原图旁标模块和关系，解释具体做法（M04、M05）。
4. **横向归纳**：从样本中提炼共性、差异与模式（M06）。
5. **逐主题收束**：每节明确可借鉴点与应用方向（M07）。
6. **推导设计**：结合目标诉求，形成原则、机会和方案（M08）。
7. **形成成果**：按需沉淀建议和资产，排列行动顺序（M09、M10）。

原有维度库用在第 3 步，仍由用户任务决定选择。无需把七步全部变成独立章节；单截图、单流程可以合并表达。复杂研究可以展开分类、旅程、模式和方案推演。

## 四、优势机制也需要完整分析

竞品研究可以围绕值得借鉴的设计开展。分析优势使用：

**具体做法 → 所服务的用户任务 → 信息/操作如何发挥作用 → 可迁移原则 → 对目标产品的应用方式。**

例如页面将资源介绍、内容目录和获取操作分为相互对应的区域，可以分析这些区域分别支持价值判断、范围判断和行动；跨样本提炼为可变的介绍页结构，随后结合目标内容确定信息顺序。无需先给这项设计制造一个问题。

界面事实、作者操作记录和预期效果按现有证据规则区分。方法学习记录主要呈现借鉴和应用；必要边界用于保证迁移准确，不占据报告主线。

## 五、后续新案例如何进入方法

每次只记录有用变化：新增做法、深化已有做法、补充适用场景、合并重复规则。保留“参考做法—方法价值—融入位置—使用示例”的学习记录。用户要求融入方法时更新实际入口和受影响参考；用户只要求阅读时先交付提炼。以最新纠正为准，不把方法学习擅自改成案例质量审计。

## 六、从方法进入专题和示范

通用方法负责选样、分类、旅程、拆解、归纳与设计推导；专题负责把关键观察问题问具体。按研究任务选用 [AI 任务](ai-task-analysis.md)、[服务履约](service-fulfillment-analysis.md)、[内容付费](paid-content-analysis.md)、[容器与动效](container-motion-analysis.md)。页面层级、比较字段、操作暗示等通用细节放在 [分析方法](analysis-result-design.md)，避免各专题重复维护。

[分析示范](analysis-worked-examples.md) 展示观察、机制、原则、目标取舍和验证如何衔接。学习记录区分原报告明确呈现的做法与我们延展的问题/教学示例；后者不能写成原报告发现。新材料优先补充缺失方法、适用边界或变体；已覆盖内容合并，不因品牌或案例数量增加就新增维度。
