# AI 任务与结果分析

在研究生成、推荐、规划或对话任务时使用；普通服务页面不因含 AI 品牌就启用。按实际研究问题选下列主题，与服务履约或内容付费专题可组合。分析单位是同一用户任务、输入条件与状态，不是模型品牌总排名。

## 1. 入口与需求表达

- 对多个入口记录位置、能力文案、触发场景、携带对象/条件、落地状态；区分功能分工与重复入口。
- 比较自由输入、模板、选项、追问的协作。每个字段说明为什么需要、在哪一步使用、必填/可选、来源为用户输入/已有信息/系统推断。
- 按问题选择需求明确与需求未定的情境：未定日期能否继续；能否跳过、改选或补充选项外需求；追问是否重复已有条件。
- 观察键盘出现后的可见区域、当前输入、已选条件与提交操作；不能从未出现键盘的图判断遮挡。

输出可用“条件—必要性—收集时机—输入方式—来源—可修改范围—证据/未知”。选择控件可能降低表达成本，也可能限制个性需求，不预设选项优于自然语言。

## 2. 生成反馈与恢复

按任务检查提交、等待、部分结果、完成、失败、取消、重试与恢复。记录中断后输入、条件、已生成部分是否保留；部分结果是否明确未完成，用户能否继续阅读或操作。

界面显示的“思考中”只作为状态文案，不推断模型内部推理。耗时须有起止点、环境和样本次数；案例作者报告的耗时标为作者记录。静态材料缺少过程时，列待验证状态，不能补写实测结果。

输出“状态—用户可知信息—可用控制—数据保留—恢复入口—证据”。等待期的内容推荐是否有帮助，需结合任务中断和注意转移验证。

## 3. 回答结构与任务适配

先标回答类型，再拆内容块：

|任务|重点判断|可比较结构|
|---|---|---|
|规划|顺序、时间、约束与可执行性|概览、分段安排、路线、费用条件、修改与执行入口|
|推荐/比较|候选差异与选择理由|同口径字段、推荐理由、条件限制、核对入口|
|直接查询|能否快速得到明确答案及依据|直接结论、适用条件、来源、必要说明与后续动作|

内容块记录“类型—顺序—回答的用户问题—关联对象—可执行动作—证据”，包含文字、图片、地图、表格、卡片和操作区。标记重复内容、关键结论位置、概览与详情能否对应；不要因为回答长就判差，也不要要求全部卡片化。

原图旁的彩色覆盖层是分析标注，不能当作产品原有卡片。分开判断生成内容质量、界面组织质量和业务执行能力；文本的来源、时效、事实正确性无核验证据时保持未知，链接可见不等于来源可靠。

## 4. 局部修改与条件延续

观察用户能控制的对象、修改范围、需要保留的条件、影响说明与撤销/恢复方式。替换一个地点是否改变整份安排，必须有操作前后证据才能判断。

可用一次小变化验证，例如替换一个候选或改变天数；先列“用户希望改变—应保持—合理连带变化”，再与实际结果对照。重新生成不总是错误，重点看范围是否符合意图、连带调整是否解释清楚。

输出“修改意图—修改前—修改后—保留条件—连带变化—恢复方式—未知”。只有编辑按钮时，结论限于入口存在。

## 5. 保存、找回与业务承接

分别确认已生成、可编辑、已保存、可找回、可执行，不能合并成一个成功状态。检查名称/版本、保存反馈、再次入口、中断后继续、自动保存与跨设备状态；无证据不推断。

进入地图、详情、预约或购票等下一环节时，核对对象、地点、日期、人数、预算等条件的传递与返回。外部跳转本身不构成缺点；具体分析重复录入、对象对应、返回成本。相关任务可继续用 [服务履约](service-fulfillment-analysis.md)。观察承接不要求实际交易，也不扩大操作授权。

最终在当前报告维度中写用户决定、机制、证据、适用条件、目标取舍与验证；以上表格按需要选用，不新增强制 JSON 字段。写法见 [案例示范](analysis-worked-examples.md)。
