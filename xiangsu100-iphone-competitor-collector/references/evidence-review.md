# 精选截图 HTML 与分析前复查

固定顺序：连续采集 → 内部逐动作验收 → 整理精选截图并归档冗余 → 交付 HTML → 用户复查（若要求） → 单竞品分析 → 多竞品证据齐备后横向对比。

## 精选的定义：去重后保留全部独立页面与状态

“精选截图”默认指去重后的完整截图集，不是少量代表图、亮点图或分析配图。不得按审美、分析重要性、篇幅或固定张数删去独立页面。分析正文可选少量配图，但必须与完整去重图库分开标明。

- 相同页面、相同对象、相同状态、相同可见内容，重复采集只展示一张清晰完整的代表图。
- 不同页面、商品、弹层、筛选/选中结果、展开状态、价格/规格、加载/空/错误状态都保留。同页滚动后出现新内容也保留，不能只按页面名称合并。
- 仅时间、电量、悬浮控件位置、无业务含义的动画或搜索占位词变化，不自动算新状态；合并前检查是否改变可读内容或可执行动作。动态商品/价格变化不能当成噪声。
- 先检查文件哈希找完全重复，再逐组看图与事件/快照判断状态重复。相似度和文件名只能辅助；不确定是否新增信息时先保留。
- 返回同一页面且画面未变，可在图库合并展示，但返回/恢复操作的原图、事件和时间仍须保留并关联到代表图，不能因此删掉流程证据。
- 每张合并图必须记录代表图编号与来源、合并原因、是否完全相同。所有原图保留；原始数量 = 去重保留数量 + 重复数量（如有其他限制须单列，不能算重复）。
- 隐私展示限制单独记录，不能把含隐私的独立页面误标为重复或悄悄漏掉；按授权提供本地原图或必要的脱敏展示，并保留状态覆盖记录。
- 主报告直接展示完整去重集，同时在顶部提供“全部原始截图”入口、重复映射和准确数量；原图按采集轮次与时间可浏览、放大、打开，不只给目录或 JSON 路径。
- 修改已有图库时保留稳定编号，新图追加编号；可按采集順序展示而不强行重新编号。同步更新图库、原图页、数量、筛选、来源清单和覆盖记录。

## HTML 交付格式

沿用已确认的美团拼好饭截图浏览页形式，生成一个本地可直接打开、无外部服务依赖的 `index.html`：

- 顶部显示竞品/频道、采集范围、原始/去重保留/重复数量及当前复查状态。
- 按任务阶段分类并支持切换，例如入口浏览、详情评价、店铺信任、筛选返回、SKU。阶段按项目调整。
- 每张截图有稳定编号、标题、简短保留原因、原始图片编号/来源及采集时间；直接展示缩略图，点击可放大。
- 同名页面发生价格、规格、筛选或返回变化时，明确标注；不能把必要前后状态作为冗余删除。
- 提供逐张取舍说明与机器可读来源清单。精选图片放独立目录，归档图片和原始运行证据可追溯。
- 写明展示顺序是否按主题编排；跨采集轮次的图不能伪装为连续操作。保留观察、推断和缺口的界限。
- 复查提示简短：用户可按截图编号指出遗漏、标注错误、应保留/去掉的图；不要求逐图审批。

建议保存 `index.html`、精选截图目录、归档目录或索引、整理说明 Markdown、整理清单 JSON。不要修改截图像素来伪造状态；隐私处理遵守主 Skill。对当前已有合格 HTML 直接复用和更新，不重新生成另一套重复页面。

## 流程状态与复查

在 `journey-plan.json` 的对应 App 下登记 `evidence_review`：

- `status`：`ready_for_review` / `changes_requested` / `approved` / `waived`。
- `gallery_path`、`manifest_path`、`selected_count`、`archived_count`。
- `review_requested_by_user`、用户反馈或确认的来源；没有确认时不得预填 approved。

用户明确要求先复查时，交付完整可检查的 HTML 后，在此阶段一次性等待；无需再问“是否要生成复查页”。采集过程中的截图回传继续遵循不中断规则。用户已经明确要求直接开始分析时，不为重复确认而停下；登记其推进指令即可。不能根据打开页面、工具完成或等待时长推断认可。

收到修订后，更新同一精选集、来源清单和覆盖记录；稳定编号尽量保留，新图追加编号，移除图保留归档映射。仅针对具体缺口补采，不能默认重跑整款 App。

## 最小验收与分析交接

核验每张精选图存在、来源可追溯、未意外修改像素、数量准确；实际打开 HTML 检查分类筛选和点击放大。无需为这一步重新操作手机。

通过复查后，以研究问题 → 用户任务 → 竞品机制 → 目标产品适用性与局限组织分析。报告引用精选编号，同时保留原始事件/快照/截图来源，原有报告 schema v2 不因精选编号而改变。其他竞品未采时，只做已采竞品分析，不宣称完整横向结论。
