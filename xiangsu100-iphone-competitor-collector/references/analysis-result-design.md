# 竞品分析维度与结果表达

本参考优化的是分析判断和交付阅读顺序，不新增固定页面清单，也不改变单竞品 `schema_version: 2`。默认服务一次完整竞品分析：围绕本轮问题与用户任务选择维度、对比证据并形成结论。不同用户路线直接纳入本轮分析；需要设计取舍时使用本参考的方案收敛要求。只有用户选择建立长期基线或跨期比较时，才按 [周期研究](research-cycles.md) 交付观察、变化与缺口；它不是普通分析的前提。竞品材料服务于判断，不以展示了多少截图、功能或模型为质量指标。

纯机制探索复用本文的任务、观察、解释与可比性方法，按 [探索报告](exploration-report.md) 收尾；下文目标产品取舍、方案卡片、行动优先级和页面调整只适用于设计决策，不能作为探索任务的必填要求。

## 从参考报告吸收方法

用户提供优秀报告供学习时，按 [报告方法学习](report-method-learning.md) 提炼“具体做法—方法价值—融入位置—以后怎么用”。优先学习它如何选样、分类、梳理旅程、拆解截图、归纳模式及推导方案；无需把参考报告转成质量评审对象。

实际分析按以下顺序组织，已有步骤可合并：

**明确研究问题与竞品角色 → 对齐业务分类和用户旅程 → 拆解关键模块与流程 → 横向提炼共性/差异 → 每个主题形成可借鉴结论 → 回答研究问题；需要改版时，再结合目标诉求推导方案、输出建议及按需复用资产。**

- 业务分类解释“哪些对象可以放在一起比”；用户旅程解释“这些页面为什么一起看”。
- 原截图和模块抽象配合使用，标注区域的职责、顺序、关系；从具体设计细节说明机制。
- 同一主题分析后先给局部结论，再在最后汇总；章节结论能回到原图和对照，不靠读者自行归纳。
- 归纳既记录共同模式，也保留因业务而形成的变体。竞品优点可以直接分析为可借鉴机制，不必先转写为问题。
- 需要设计探索时，展示“依据—诉求—原则—机会—方案”的推导；通用能力研究可同时输出“当前建议”和“复用模板”。使用已有字段及章节/附件承载，不为方法变化自动增加 schema。

## 一、从用户决定生成维度

先列最新确认的研究目标，标明主要改版目标、明确要求支持性核对的目标及本次不处理的范围。若用户修正旧任务书，保留旧目标作为历史，当前结论按新目标写。用户认可“上一版分析内容”，是认可该分析的框架与证据，不等于确认目标产品现状满意；应保留该维度和条件性设计判断，不得自动降为“保持现状”。目标优先级及其原因、目标产品的体验判断分别记录；支持性核对可以由当前范围决定，不能据此推断现状满意。把每个目标展开为用户在真实任务中的决定，例如“去哪找”“选哪个”“当前条件下得到什么”“改变选择后会怎样”；一个目标可以覆盖入口、首页分发、卡片、筛选、详情、商品信息和规格等多个触点，不因页面多就拆成互不关联的改版方向。将用户意图与其原因假设分开：发现反向证据时保留原方向，给出依据、疑问、建议和待确认调整；用户接受后才改目标。每个决定只设一个主维度，并关联目标与任务阶段。维度数按研究范围选择；没有证据的触点标为待验证，不用竞品名称或页面类型凑数。

设计决策的每个维度至少回答六件事；纯探索的第 5 项写机制适用条件与代价，第 6 项写如何检验解释，不要求目标产品改动：

1. **用户决定**：用户要回答什么问题、完成什么任务，成功表现是什么。
2. **必要信息与控制**：该决定需要哪些对象、条件、来源、反馈和返回能力。
3. **实际机制**：各竞品在已走路径中怎么组织信息和操作；记录实际路由、状态及证据深度。
4. **决策支持与阻力**：机制帮助了什么判断，要求额外记忆、比较或操作什么；有反例时同时写。
5. **适用性与代价**：目标产品是否具备内容、字段、权限、业务和维护条件；选择采用、调整、保留、暂缓或拒绝。
6. **验证**：最小可测试改动、对照任务、观察指标，以及会推翻当前判断的结果。

认知走查、信息架构、界面和交互评估是解释同一任务决定的镜头，不是四份重复的问题清单。一个发现只在最直接影响的决定处展开，其他章节交叉引用。发现的直接观察和专家解释分别标注，不把竞品问题写成目标产品已证实的问题。

用已有字段写清一条判断链，不再新增一套分析表：

|判断环节|落在哪些字段|写作边界|
|---|---|---|
|目标与可观察问题|goal_id、user_decision、necessary_support|把“更高效”转成可观察的用户任务和成功表现|
|竞品事实|cells.mechanism、status、evidence_refs|写图中可见内容或已发生动作；静态图不能证明点击、返回或用户效果|
|解释与反例|decision_support、friction、unknown|说明为何可能支持/妨碍判断；未测效果标为推断，反例或替代解释放在同一处|
|目标产品取舍|target_evidence_ids、target_decision|对照目标现状，再写适用条件、保留项、代价与备选；成本未知写缺口，不用“低成本”冒充估算|
|行动与验证|redesign_summary、validation、falsifier|引用维度落到具体页面；写会推翻建议的结果，结尾不重抄完整竞品分析|

例如：截图可见“已保存”提示是事实；“可能减少重复确认”是解释；“在目标产品缺少该反馈且测试出现误判时补充提示”是条件建议；只有任务测试结果才能支持效果判断。目标产品已有反馈时，可保留或只核对误解点。不要为了字段齐全编造问题。

## 页面细节与专题问题的使用

先按用户决定选择观察问题，再按需进入 [AI 任务](ai-task-analysis.md)、[服务履约](service-fulfillment-analysis.md)、[内容付费](paid-content-analysis.md) 或 [容器与动效](container-motion-analysis.md)。同一任务可组合专题，相关问题在原有维度内展开，不机械增加章节或总分。

通用页面观察细化到下列动作：

- **入口与条件**：记录位置/文案、触发场景、带入对象、落地状态；字段为何需要、何时使用、是否已有，必填/可选和修改方式。只有静态图时不把入口与落地连成实测路径。
- **结构与顺序**：写出实际模块顺序，对应用户判断顺序；标记必要、补充、重复信息，检查概览与详情的对应。同类区域用一致语义图例，原图与抽象结构并排。
- **比较支持**：选择同一任务所需字段，核对日期、规格、数量、权益和用户状态的口径；分析是否需要反复回看或记忆。价格、优惠条件和费用理解归入决策支持；商家资质、服务保障等按实际信任问题展开，避免重复。
- **视觉与操作暗示**：分析价格/优惠层级、标签与主操作的强调关系、横向内容半露出、选中和链接状态。使用“元素—表达方式—服务的判断—潜在代价”，不要仅写清晰、美观。静态的半露出只证明提示形式，是否可滑、是否被发现需另证。
- **分支与恢复**：记录触发条件、对象、变化、取消/完成、返回保留内容；键盘或面板出现后检查必要内容与操作是否仍可见。少步骤不等于更好，需保留必要核对机会。
- **信息依据**：主张对应来源、时间、适用对象/条件和核对入口；作者判断、界面事实、性能测量及效果推断分别表达。历史事实不自动代表当前产品。

字体、色值、热区尺寸无可复核来源时不填精确值；静态材料不能证明动效、返回或用户理解。更多细节只在影响本轮决定时展开。写作示范见 [analysis-worked-examples.md](analysis-worked-examples.md)。

## 二、可比性与证据深度

横向比较先写共同任务和样本条件，再比较机制。不同对象、规格、数量、价格口径、地区或履约方式不一致时，比较信息表达和决策过程，不排价格或体验总名次。把“入口可见”“内容已打开”“操作闭环已完成”“返回已核验”“未验证”“用户排除”分开记录。

每个横向单元的最低信息为：竞品/频道、实际动作或状态、证据编号、证据级别、与共同任务的可比条件、未知项。未采集对象不计零分；证据不对称时只给局部结论或待验证。不默认增加定位矩阵、独立机制拆解或机会象限；机制直接写在当前维度，行动排序集中到最后总结。

## 三、设计决策：先给摘要，再给证据

交付按两层阅读：

**第一页：目标到方案的对应。** 先给一张简短映射：研究目标 → 涵盖的用户决定/触点 → 竞品观察 → 目标产品取舍 → 验证任务。再展示最多三个要验证或采用的方向，不强制三个。明确为支持性核对的目标可以只写“保持现状”及证据缺口，不必制造新方案；不能因用户认可前版分析而作此判断。每个方向用下列短卡：

| 字段 | 写法 |
|---|---|
| 判断 | 一句话说明目标产品下一步要做什么决定，而非宣称已获得收益 |
| 证据 | 2–4 个最关键的来源编号；区分观察与解释 |
| 适用条件 | 依赖的内容、规则、权限或对象范围；未知直写未知 |
| 最小改动 | 可进入原型或任务测试的最小方案，也可保持/暂缓 |
| 代价与备选 | 增加的复杂度，以及没选另一方案的原因 |
| 验证与反证 | 用户任务、观察指标和何种结果会推翻建议 |

摘要前有一句证据范围：采了哪些独立平台和频道，哪些关键分支缺证。若目标产品没有本次实测，只写“设计假设/待验证”，不得写“已证明目标产品存在此问题”。

**第二层：可追溯证据。** 用共同任务流程表、关键机制对照、少量并排画面和来源索引支撑摘要。完整去重图库和逐步走查保留在独立报告或可折叠附录。主文不把同一截图在定位、流程、认知和单屏四处重复讲述；来源编号稳定，点击能回到原图/快照/事件。

## 四、设计决策的最后总结：优先级与页面调整

按目标分析完竞品后，必须有独立的最后总结，不能以证据列表或“建议优化信息层级”结束。开头可以先给简短结论和跳转，结尾给完整行动清单。每个已分析维度都有行动或明确的保留/暂缓结论，不把最多三个首页摘要卡片变成研究范围上限。

**优先级表**：按本轮行动顺序列出P1（先处理）、P2（随后）、P3（后续考虑），同级内给顺序；不强制凑齐三级。写对应目标、具体建议、为什么排在这里、前置事项和当前阶段。阶段必须区分先做原型测试、先补证、进入实现、保持、暂缓、不采用。P1可能是先补证，不等于必须立刻开发；主要研究目标不自动等于P1。没有业务数据不编评分、收益或精确工时。

排序依据结合：对当前用户任务的影响、目标产品证据是否充分、用户当前范围、实现与维护代价、依赖是否满足。说明为什么先于其他建议，而非每项都写“重要”。信任等维度即使本轮后做，也保留原分析，不能推断没有问题。

**页面调整清单**：逐项回答“哪个页面/模块 → 当前已见情况或未知 → 调整后的信息顺序、内容或交互 → 保留哪些能力 → 默认/变化/返回/异常等关键状态 → 怎么验证”。同一方案可跨页，依赖先后明确；同一页面的重复建议合并，不让不同目标给出冲突布局。未观察的独立页面不凭空创造，先核对是否存在。

例：写“文章列表 / 收藏反馈：保留收藏入口，在操作位置显示已保存状态；返回列表保留原位置；用保存后继续阅读任务验收”，比“提升反馈效率”更可落地。例子不规定所有产品必须采用相同布局。

最后写本轮不做什么及理由。采用/调整必须说明条件，保持/暂缓也算有效结论；研究报告不自动承担未经要求的开发、上线或高保真出图。字段契约与渲染由 `redesign_summary` 承载，结构完整仍需人工判断质量。

## 五、设计决策结果质量自检

- 每项建议都能回答“来自哪张图/哪个动作、支持的是哪一步判断”。
- 每项方案都标明对应的已确认研究目标；每个主要目标都有设计决定或明确的待补证结论，支持性目标不会被误写成主要改版方向。
- 每项比较都写可比口径；证据深度不足时有局部结论或待验证，而不是空白评分。
- 每个设计动作都写目标产品适用条件、最小版本、代价和备选。
- 优先级区分用户任务影响、证据强度、项目相关性和实施条件；没有用户/业务数据时不编成功率或收益。
- 摘要与详情没有相互矛盾；历史状态不覆盖最新范围；读者不翻完长报告也能理解“建议先验证什么、为什么”。

结构检查能发现缺字段和断链，不能证明结论有用。首次建立报告形式时可用已有证据做一页样张；已有明确修订任务时直接修改受影响内容，不新增样张审批或自动增采。判断是否清楚仍需项目负责人和任务测试验证。


设计交接与当前结论同步采用 [research-delivery.md](research-delivery.md)：已有材料不触发设备准备；新报告严格检查目标和目标产品证据；成图后逐项记录实际目标检查，未落实标为待修订；所有当前派生报告登记依赖版本，上游改变后先重建再交付。
