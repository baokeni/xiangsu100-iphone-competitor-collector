# Windows 安卓 USB 分支诊断

仅用于已授权的 Windows + Android/已确认 Android 兼容鸿蒙设备适配。原生鸿蒙走 HDC。材料分析跳过设备诊断。命令由当前执行工程的受控适配器在相应授权下执行；本文件不新增运行器，静态 `plan_device_adapter.py inspect` 仍不调用 ADB、不联网、不安装。

## 判断依据与边界

ADB 是客户端、电脑端 server、手机端 adbd 三部分。USB 链路也依赖电脑端本地通信，默认 server 端口为 5037。实际端点可能被配置覆盖，应读取当前设置，不能通过向所有网卡开放监听解决本机权限问题。

2026-10-23 的 vivo S19 案例文档记录：agent-device 0.20.5 / ADB 37.0.1 在 Codex 中先报 `failed to create fdevent interrupt socketpair: Invalid argument`、`could not read ok from ADB Server`、`failed to start daemon`；取得本轮本地通信权限后服务能启动，但列表为空。Windows 已识别手机及 ADB Interface；用户在普通 PowerShell 完成初始化和手机授权后，Codex 可打开京东并取得 1080×2400 截图。

这是**外部案例文档的记录**，不是本包维护环境重新实测。它支持分开诊断服务启动、枚举和授权，不支持锁定空列表由 USB 隔离、进程生命周期或某个驱动导致。版本号用于案例追溯，不作为默认升级/降级目标。Helper安装、后续锁屏及会话丢失分别归类。

## 诊断顺序

**确认执行位置和工具 → 检查/复用 ADB 服务 → 获取设备状态 → 必要时对照 Windows 接口与普通 PowerShell → Codex 复查 → agent-device/Helper → 目标 App 冒烟。**

1. 确认手机接在当前执行电脑；区分原生 Windows、WSL、容器、远端和受限终端。核对 ADB 实际路径、版本、已知服务版本/端点和 agent-device 版本；多套 ADB 时先选择兼容路径，不让不同客户端轮番争用服务。不能仅因 `adb version` 成功就认为可发现 USB 设备。
2. 读取本轮平台实际授予的权限/作用域；未知填 `unknown`。USB 连接不代表本地 socket 一定获准。若授权仅为 `turn`，下一轮重新检查，不把它描述成永久有效；授权需沿平台支持的方式申请，不以管理员运行或关闭保护代替。
3. 尽可能先用主机只读信息查看现有 ADB 进程、监听及已知启动者。PID/端口存在只证明存在进程/监听，不能证明它健康或兼容。随后在授权下查询一次 `adb devices -l`；它在服务不存在时可能自动启动服务，不能归类为纯静态检查。版本不匹配的客户端也可能重启服务，发现不匹配先核对路径，不继续反复探测。
4. 同时保留退出码、stdout、stderr和超时；不能只解析 stdout。**服务错误/非零退出/超时优先于列表内容**，不得把失败或半截输出转成“空列表”。先对照下表，再采取一个有依据的恢复动作，复查失败步骤。

|当前证据|判断与下一步|不能作出的结论|
|---|---|---|
|socketpair、daemon、server连接失败或超时|电脑端服务/本地通信未通过；保留错误，检查执行环境和当前权限。服务不可读时设备授权状态记未知|不能让用户先反复寻找手机授权弹窗，不能断言手机没连上|
|命令成功且无设备行|仅说明该客户端当前未枚举到设备；只读检查Windows的目标手机与ADB接口。接口未识别/异常才针对线、端口、调试设置或OEM驱动继续定位|空列表不等于手机不支持、驱动损坏或尚未授权|
|Windows手机及ADB接口正常，但Codex仍空列表/服务异常|比较两处执行位置、ADB路径/版本和端点；满足下节条件时做一次普通PowerShell对照|接口正常不能证明隔离环境可访问，也不能完全排除间歇性连接问题|
|`unauthorized`|用户解锁手机并核对RSA调试授权，再复查；无弹窗则记录实际情况，继续查授权/服务差异|不能自动点击信任，也不以删除ADB密钥作为默认修复|
|`offline`|检查当前连接/锁屏/服务状态，按新证据选择一次恢复并复查|不能无界重试或直接更换自动化框架|
|多设备或模拟器并存|明确选择研究手机；设备命令带 `-s SERIAL` 或所装工具等价选择参数|不能默认使用第一台，不能将模拟器当成本案例真机|
|选定设备为`device`|ADB连接通过；继续验证所选手机上的agent-device会话、Helper和目标App|不能直接宣布截图、结构、导航或研究完成|
|服务健康/设备为`device`，agent-device会话失效|按已安装版本恢复选定会话，重新取截图/结构并定位|不能把会话丢失直接归为ADB服务失败|
|Helper安装待确认、锁屏或需登录|只提示用户完成当前人工步骤，再复查该步|不能把这些后续问题追溯为最初空列表的已确认根因|

不默认执行 `adb kill-server`，不盲目 `start-server`，不删除密钥、改全局网络或自动换无线调试。若证据确需重启，先说明受影响的共享ADB会话、操作和恢复方法，遵循当前授权边界。普通终端对照也不得用于绕过平台明确的安全拒绝。

## 普通 PowerShell 对照与初始化（一次）

触发条件：任务已授权设备环境诊断；Codex内服务/发现异常；Windows已识别目标手机及ADB接口；当前环境已有的有界检查仍未解决；平台允许该诊断路径。若这些证据缺失，先补对应检查；明确安全拒绝时停在授权流程，不换终端规避。

先按 [AI先处理的规则](platform-adaptation.md#故障时由ai先处理降低同学操作成本) 检查可用能力。若已有授权的电脑控制工具可在同学电脑打开普通PowerShell，且平台允许这一对照，由AI代为打开、核对路径和执行查询，并自行读取结果；不要默认把终端操作交给同学。若只能人工完成，下面是AI分步引导的操作参考，**每次只呈现当前必要的一步**。优先使用已核对且与现有服务兼容的ADB完整路径；不要默认要求管理员终端。下面先查看路径和版本：

```powershell
Get-Command adb -All | Select-Object Source
adb version
```

确认与Codex选择的是同一兼容工具后，仅执行一次：

```powershell
adb devices -l
```

若PATH有多套ADB，AI应根据实际路径给出PowerShell调用运算符 `&` 加带引号的完整路径，替代上面的裸 `adb`；PATH未配置时也使用已发现路径，不要求重装工具。用户在手机上完成实际出现的调试授权，不主动要求撤销已有信任。

- 普通终端得到目标 `device`：AI回到Codex、在当前权限下复查同一兼容ADB路径/端点与选定设备，优先复用正常服务。普通终端成功不自动等于Codex成功。
- 普通终端也是空列表/服务失败/未授权：保存真实状态，回到对应分支，不把初始化写成成功，也不反复要求再开终端。
- 普通终端成功、Codex仍失败：记录“普通终端可用，当前执行环境未通过”；保留差异和最小待解决条件。材料分析可继续，用户要求的自动采集保留为阻塞，不静默替换路线。

同一原因复现且没有新证据时停止重复尝试。一次人工对照后若需要再做，必须说明新变化与为什么能改变判断，不能机械重教USB设置。

沟通示例（仅在需要人工打开终端且相应证据已取得时使用）：

> Windows已识别手机和ADB接口，我也检查了当前Codex环境，设备列表仍为空。下一步需要对照普通PowerShell；当前我无法代你打开这个窗口。请先在开始菜单搜索并打开“PowerShell”，看到命令窗口后回复“已打开”，我再给你下一步。

窗口打开后才提供已填好实际路径的单条查询命令；只有确需核对手机授权时再提示该步。AI可直接读取结果时自行读取，不能读取时才请同学回复device、unauthorized、offline或空列表，无需整理长日志。

## 跨轮次与采集验收

每轮继续设备任务前轻量复查权限作用域、服务、选定设备和会话；重连/版本变化/恢复后刷新截图与结构。未变化的研究目标、USB设置和型号信息直接复用。记录两个独立状态：ADB服务健康与agent-device会话健康；不知道启动者或生命周期时填 `unknown`，不推断。

在同学电脑完成：明确选定且已授权设备 → 目标App打开 → 截图保存 → 当前页面结构读取 → 无副作用导航/滚动/返回并保存前后证据。Helper须按所装版本核对，首次安装弹窗由用户处理；当前官方文档命令不一定适用于案例旧版本。结构不可读则记录部分能力及降级条件，不能宣称完整采集就绪。

只通过ADB连接标记“连接通过”；只有截图标记“目标App截图通过”；所需冒烟证据齐全才标记“采集就绪”；任务覆盖与分析完成才标记“研究完成”。本案例文档只支持其所述连接/打开/截图结果。静态规则检查与案例回放均不能充当Windows真机回归。

## 诊断留档（沿用当前任务证据目录）

保存 `device-diagnostics.json` 或等价结构化记录，不另造研究报告schema。每步包含时间、执行位置、命令参数、退出码/超时、结果/错误、证据引用、失败层级、下一步；最少登记：

- host/架构、执行环境、手机系统来源与版本；ADB路径/版本、agent-device版本、服务端点。
- 当前权限状态、scope、检查时间；服务状态、PID/版本、启动者及已知生命周期（未知明确标记）。
- Windows手机/ADB接口状态、当前设备列表、明确选定设备；普通终端结果与Codex复查结果分别记录。
- agent-device会话标识/状态、Helper状态、App包名、各项能力检查和证据路径。
- 已尝试恢复及次数、尚未定位原因、阻塞或下一步；`ready_for_capture`默认false，只有当前所需实测全部通过才改变。

本机执行记录保留定位设备所需标识；共享副本使用一致代号脱敏序列号、用户名和本机路径，不保存ADB私钥、登录凭据或无关用户数据。原始日志先保存在任务允许的位置，共享时输出脱敏副本，不覆盖首个失败。

## 升级验收场景

|输入场景|应有行为|
|---|---|
|服务socketpair失败且stdout为空|归电脑服务/通信层，保留错误，设备状态未知，不误报空列表|
|命令成功空列表，Windows接口正常|触发环境对照条件判断，不先建议重装驱动|
|普通PowerShell为device，Codex未复查|只能报告普通终端通过，不宣布Codex/采集就绪|
|普通终端及Codex均为device，目标App仅截图通过|保留部分能力，补结构/安全导航/返回证据|
|新轮权限未知/服务不可达|重新检查当前权限与服务，不沿用历史成功|
|unauthorized / offline / 多设备|分别人工授权、有依据恢复、明确选择，不混成同一故障|
|设备device但会话失效 / Helper待安装 / 手机锁屏|分别恢复会话或提示当前人工步骤，刷新页面证据|
|同一失败再次出现且无新证据|停止该重复尝试，给出最小可执行下一步|

这些是验收要求；只有保留实际执行产物后才能登记通过。

## 官方资料（2026-10-23核对，执行时复核所装版本）

- [Android ADB](https://developer.android.com/tools/adb)：客户端/服务端、默认5037、RSA授权、设备状态与设备选择。
- [ADB命令手册](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md)：端点和设备参数、服务命令；不因此推荐开放全网监听。
- [Windows OEM驱动](https://developer.android.com/studio/run/oem-usb)：按目标设备查对应驱动，不能把重装作为所有空列表的默认解法。
- [agent-device已知限制](https://oss.callstack.com/agent-device/docs/known-limitations)：OEM首次Helper安装确认及WSL工具路径差异；新文档不能证明0.20.5包含新诊断命令。
