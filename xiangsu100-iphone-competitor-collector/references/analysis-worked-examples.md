# 从观察到设计取舍：分析写法示范

以下为教学示例，演示从参考材料提炼出的分析方法。示例中的截图编号、产品条件及验证结果不是已发生的研究事实；实际分析应替换为本项目证据，不得把假设复制成竞品结论。原参考报告的品牌、页码和图件留在项目学习记录中。

## 示例一：AI 推荐列表的比较

**示例前提：** 假设两张截图呈现同一推荐任务：甲逐项用长段落说明候选，乙用相同字段排列候选；未提供点击或用户测试记录。

**观察：** 甲的地点、价格条件与适合人群分散在段落中；乙把对应字段放在相近位置。需先核对候选条件是否可比，缺少的字段如实标记。

**任务与机制：** 用户需要选出符合预算和距离要求的候选。相同字段可能减少跨段查找和记忆，但精简说明也可能丢掉影响选择的理由。这是机制推断，不是效率测试结果。

**可迁移原则：** 让决定性字段便于对照，解释与细节仍可访问；不是把所有回答改为表格。

**目标取舍：** 若目标任务确实要求反复比较且已有稳定字段，可先在推荐区增加简短对照，保留原解释入口；若字段不可比，先改善标签和信息顺序，暂不做统一表格。

**验证与反证：** 用相同选择任务比较两种原型，观察查找、回看及条件理解错误；若表格导致重要差异被忽略，则调整字段或放弃该方案。局部编辑、保存与跳转能力仍需另有证据。

## 示例二：车主服务中的凭证承接

**参考方法：** 先分服务阶段，再比较相邻阶段如何传递对象和状态。

**示例前提与观察：** 假设材料显示消息中有预约信息，另有订单凭证页，但没有点击录像。可以确认两个信息触点存在，消息是否直达对应凭证仍未知。

**任务与机制：** 用户到店时要找到本次预约的正确凭证。若消息携带预约标识直达对应订单，可减少重新查找；同时需要防止过期或取消消息指向可误用的状态。

**原则与应用：** 按任务对象衔接触点。目标平台支持可靠订单关联时，提议消息落地显示预约时间、门店及凭证状态；若不支持，先完善订单内检索和状态说明，不宣称一步直达已实现。

**验证：** 用测试订单验证有效、取消或过期消息的落地对象和返回路径；线下核销效果不由截图推断，也不为验证界面而自动创建真实订单。

## 示例三：付费内容介绍页

**参考方法：** 将原图分成语义模块，从跨产品共性中抽出基础结构，并保留资源变体。

**示例前提与观察：** 假设课程页可见课程身份、介绍、目录、试看片段和开通操作。按图中顺序记录，不能将分析色块当作原产品卡片。

**任务与机制：** 用户依次需要辨认内容、判断价值与范围、确认当前获得方式。目录和试看分别提供范围与样例依据，开通区需要解释对应权益。

**原则与应用：** 让价值判断、范围核对和获取操作形成可往返的关系。目标若同时提供单课与会员，先比较权益字段和当前内容覆盖，保留试看；咨询服务则按服务对象与交付范围调整模块，不强套课程目录。

**验证与反证：** 请用户说明试看范围和付费所得，再取消开通回到原内容；若只是增加模块却造成权益误读，重新调整分组。未进行测试时不写提高转化。

## 示例四：临时查看的容器选择

**参考方法：** 从研究依据推导原则、场景机会与方案，再用状态序列说明交互。

**示例前提与观察：** 假设研究材料给出列表中展开临时详情、关闭后回到列表的设计连图。只能确认方案意图，不能确认线上返回位置或动效速度。

**任务与机制：** 用户临时核对信息后继续比较。局部面板可能保留背景参照，但说明空间、键盘遮挡或嵌套操作可能使它不适合复杂编辑。

**原则与方案：** 以保留比较上下文为原则，同时比较面板与独立页。短时查看可先试面板；复杂输入可试独立页并保存列表条件和位置。明确初始、展开、完成、取消、返回各状态。

**验证与反证：** 检查用户能否读到必要信息并回到原候选；若面板遮挡导致误操作，则调整容器。用视频/原型另查动效连续性，静态图不证明流畅。

## 将这些示范写进实际报告

一条结论依次交代“证据与可见做法 → 用户任务 → 机制解释 → 可迁移原则 → 目标适用条件与取舍 → 具体页面动作 → 验证/反证”。可以直接提炼优势，不必先制造缺点。

按现有契约映射到 evidence_refs、mechanism、decision_support/friction、target_decision、validation/falsifier 与 redesign_summary；示范不是一套新 schema。目标产品材料不足时给条件性建议；用户只研究机制时，不扩展为完整改版项目。
